# 18 Kasım — Commit tamamlandıktan sonra yanıt kaybı

npm run test:android:reply-loss eklendi. Yalnız yerel demo Firebase emülatörleri ve ayrı named FirebaseApp hesapları kullanılır. İki SDK bağlantısı da aynı rastgele yerel test UID'sine giriş yapar; yönetici yetkisi veya servis anahtarı yoktur. Ana bağlantı TCP proxy üzerinden, gözlemci bağlantı ayrı geçici 8088→8086 loopback yolundan gider. Kontrol servisi koşuya özel nonce ile sınırlandırılmıştır.

Proxy'ye yalnız sunucudan istemciye dönüş verisini düşüren mute modu eklendi. İstekler sunucuya iletilir; yanıt byte sayacı tutulur. Geri bağlantıda eski socket'ler kapatılıp SDK'nın yeniden bağlanması sağlanır. Ortak kontrol yardımcısı TCP ve yanıt kaybı testlerinde paylaşılır. Proxy koşucusu ProcessRestart/TransportCut/ReplyLoss modlarından yalnız birini kabul eder; kendi eklediği reverse eşlemelerini kaldırır. Cihazın genel ağ ayarları ve Play paketi değişmez.

lostCommitReplyKeepsQueueUntilIdempotentConfirmation ilk transaction sunucu okumasını kontrollü bariyerde tutar. Dönüş trafiği mute edildikten sonra transaction serbest bırakılır. Doğrudan gözlemci Source.SERVER ile şehrin gerçekten silindiğini doğrular; aynı anda asıl SDK Task henüz tamamlanmamış olmalıdır. Gerçek dönüş byte'larının düşürüldüğü ayrıca doğrulanır. Dispatcher'ın bu test çağrısındaki 4 saniyelik timeout'u CitySyncTimeoutException üretir; üretimdeki 60 saniyelik değer değişmemiştir.

Uzak commit gerçekleşmiş olmasına rağmen onaysız kalıcı kuyruk ve reservation bekleme sınırı korunur. Dönüş yolu açılıp eski Task sonucu gözlendikten sonra da iptal edilmiş dispatcher yerel onay yazmaz. Geç Task'in Boolean sonucu veya UNAVAILABLE ile bitmesi kabul edilir; kaydın sunucuda hâlâ silinmiş olması, kuyruk revision/bekleme durumunun değişmemesi ve yalnız ilk silmenin aşamalanması zorunludur. Bekleme süresi dolmadan yeni gönderim engellenir. Enjekte edilen saat sınıra alınca olmayan belgenin idempotent silme onayı gerçekleşir; ikinci bir delete aşamalanmaz ve gerçek sunucu görüntüsüyle kuyruk temizlenir.

Sonuçlar: özel yanıt kaybı XML 1 test/0 hata/0 atlama; önceki tam TCP kesintisi özel koşusu yeniden 1 test/0 hata/0 atlama geçti. Normal SDK regresyonu XML tests=11, failures=0, errors=0, skipped=3: sekiz normal senaryo geçti. Üç özel mod normal koşuda planlı atlanır; yanıt kaybı/TCP ayrı koşularında geçti, process restart bu tur tekrar koşulmadı. Konsoldaki 14/11 sayacı toplam olarak alınmadı; XML esas alındı. Node sözdizimi ve git diff kontrolü geçti. Son kontrolde proxy/kontrol dinleyicileri ve ADB reverse eşlemeleri kalmadı; emülatörler kapandı.

Bu tur üretim Kotlin veya Firebase kuralları değişmedi; test ve koşucu geliştirildi. Gerçek commit sonrası yanıt kaybı fixture düzeyinde doğrulandı. Tam Activity/ViewModel kullanıcı akışı, uygulama restart'ının aynı yanıt kaybıyla birleşimi, gerçek üretim TLS/modem/Doze, reboot/saat değişimi ve Android hesap silme uçtan uca birleşimi bu testte çalıştırılmadı. Timeout'un uzak commit'i geri alacağı iddia edilmez; test tam tersine tamamlanmış commit'in korunduğunu gösterir. Sanal bekleme saati kullanıldığı için gerçek bekleme süresi geçirilmedi.

Sırada tam açılış/kurtarma ve hesap silme birleşik kabulü ile legacy ad-only uyumluluğu var. Canlı Firebase kural dağıtımı, üretim servis doğrulaması ve Play yayın kapıları açık. Önceki JVM/UI/JS kural testleri bu tur tekrar koşulmadı. Push/release/canlı dağıtım yapılmadı.
